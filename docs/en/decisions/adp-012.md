# ADP-012 — Modern Syntax Ergonomics and Design Philosophy (Gleam/Swift Pivot)

- **Status**: Approved
- **Date**: 2026-09-26
- **Deciders**: Raillen & Poppy Team
- **Phase**: Architectural Evolution / v0.2.0

---

## Context & Cognitive Diagnosis

Aipo's initial syntax—inherited from Ruby/Lua patterns featuring keyword-based `end` blocks and fragmented mutability keywords (`fixed`, `self!`)—created measurable cognitive load for developers and particularly for neurodivergent individuals (ADHD and dyslexia):

1. **"End-Blindness"**: Repeated block closures at multiple nested levels sharing the identical textual keyword (`end \n end \n end`) caused visual fatigue, disorientation regarding active scope boundaries, and made rainbow-bracket highlighting or smart folding impossible in modern IDEs.
2. **Mutability Incoherence**: Variables declared mutability via `let` (immutable) and `var` (mutable). However, structs defaulted to mutability and required `fixed` for immutability, while methods relied on the isolated sigil `self!` instead of uniform language semantics.
3. **Structural Instantiation Asymmetry**: Dictionaries used key-value colons (`{ "k": v }`), whereas structs used equals signs (`Type{ k = v }`), creating recurring typos and mental friction.
4. **Unnecessary Conformance Ceremony**: The top-level orphan declaration `satisfy Type: Interface` created bureaucratic coupling and boilerplate, directly violating Aipo's core commitment to simplicity and clean modularity.
5. **Arithmetic Inconsistency**: Truncated integer division relied on the alphabetic keyword `div`, breaking symbolic symmetry with standard arithmetic operators (`+`, `-`, `*`, `/`).

---

## Architectural Decisions

### 1. Gleam / Swift-Style Curly Braces (`{ ... }`)
- All language blocks (`fn`, `struct`, `impl`, `if`, `while`, `loop`, `repeat`, `each`, `match`, `attempt`, `await do`) are delimited by curly braces `{ ... }`.
- Control flow conditions **do not require and do not accept parentheses**: `if x > 10 { ... }`, `while active { ... }`, `each item in list { ... }`.
- Total elimination of the `end` keyword. This enables native *rainbow brackets*, instant editor auto-closing, and unambiguous visual scoping depth.

### 2. Immutability by Default in Structs and Elimination of `fixed`
- In `struct`, all fields are immutable by default. Simply declare the field identifier (`id`, `created_at`).
- When a field requires mutability throughout the instance lifecycle, prefix it explicitly with `var`: `var status = "offline"`.
- The keyword `fixed` is completely removed from the grammar.

### 3. Key-Value Symmetry in Struct Instantiations (`:`)
- Struct instantiation adopts canonical key-value colon syntax `StructName{ field: value, ... }`, removing asymmetry with dictionary literals `{ "key": value }`.

### 4. Universal Mutability with `var self`
- The isolated sigil `self!` in mutator methods is replaced with `var self`: `fn increment(var self) { ... }`.
- Unannotated `self` remains strictly read-only. This unifies mutability rules across all language constructs: `var` is the universal keyword for mutability.

### 5. Automatic Structural Subtyping for Interfaces
- The orphan `satisfy` declaration is eliminated.
- Type conformance to `interface` is structural and automatic (Go / Luau model). If a struct implements all required methods with compatible signatures (arity, parameters, return types, receiver mutability `self` vs `var self`), it satisfies the interface automatically.

### 6. Symbolic Integer Division Operator (`//` and `//=`)
- The `div` and `div=` keywords are replaced with canonical arithmetic operators `//` and `//=`.

### 7. Preservation of the Four Loops
- The four loops (`loop`, `while`, `repeat`, `each`) are retained using `{ ... }` syntax, with ongoing telemetry monitoring real-world usage patterns.

## Syntax Comparison Before and After

| Feature | Legacy Syntax (Ruby/Lua-like) | Modern Syntax (Gleam/Swift-like) | Cognitive Benefit |
| :--- | :--- | :--- | :--- |
| **Blocks** | `if c ... end` | `if c { ... }` | Eliminates "end-blindness" and enables native rainbow brackets |
| **Struct Fields** | `fixed id \n status = "off"` | `id \n var status = "off"` | Universal immutability by default; `fixed` eliminated |
| **Instantiation** | `User{ id = "1", name = "A" }` | `User{ id: "1", name: "A" }` | Symmetrical with dictionary literals |
| **Mutator Method**| `fn inc(self!)` | `fn inc(var self)` | Unified semantics: `var` signals mutability everywhere |
| **Interfaces** | `satisfy User: Authenticable` | *(Automatic / Structural)* | Zero boilerplate; effortless library decoupling |
| **Integer Division** | `a div b` | `a // b` | Symbolic mathematical consistency |

## Implementation Impact

1. **`aipo-lexer`**:
   - Add `SlashSlash` (`//`) and `SlashSlashEq` (`//=`) tokens.
   - Remove `fixed` and `satisfy` keywords.
2. **`aipo-syntax`**:
   - Parse all blocks using `{` and `}` delimiters.
   - Parse struct fields as immutable by default, with `var` marking mutable fields.
   - Parse struct instantiations using `:` as key-value delimiter.
3. **`aipo-sema`**:
   - Verify interface compatibility structurally and automatically during type checking.
   - Validate immutable field reassignment (`AIPO_SEM_IMMUTABLE_FIELD_REASSIGN`).
   - Validate `var self` mutator receiver semantics.
4. **`aipo-formatter`**:
   - Format blocks cleanly with `{ ... }` and standard 4-space indentation.
5. **`aipo-js`**:
   - Update JavaScript emission for struct field descriptors and method dispatch.
